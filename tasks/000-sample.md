# Task 000: 작업 파일 샘플 (초기 상태)

> 이 파일은 새 작업 파일을 만들 때 참고하는 **초기 상태 템플릿**이다. 실제 작업 파일(`001-*.md` 이후)은 이 구조를 복사해 작성하고, 구현이 끝나면 체크박스를 채우고 말미에 "변경 사항 요약" 절을 추가한다. 이 샘플에는 요약 절이 없다 — 시작 시점의 문서에는 있어서는 안 되기 때문이다.

## 고수준 명세

- **목적**: 이 작업이 왜 필요한지 한두 문장으로 적는다. (예: `/projects` 목록이 더미 데이터 대신 Notion 실데이터를 렌더하도록 `getPublishedProjects()`를 연결한다.)
- **범위**: 이 작업에서 다루는 것과 다루지 않는 것을 명시한다. (예: ISR 설정은 다음 작업(011)에서 다룬다.)
- **PRD 참조**: 관련 기능 ID와 절을 적는다. (예: F1, F6, §6.1, §11)
- **리스크·미결**: 해당하는 R/U 항목을 적고 이 작업에서 어떻게 대응하는지 쓴다. (예: R3 — 페치 실패 시 빈 배열 반환으로 빌드를 실패시키지 않는다.)
- **전제 조건**: 선행 작업, 환경 변수, Notion 측 준비 사항. (예: Task 009 완료, `.env.local`에 `NOTION_API_KEY` 설정)

## 테스트 체크리스트

> API 연동·비즈니스 로직이 포함된 작업은 이 절이 필수다. 각 시나리오는 Playwright MCP로 브라우저를 직접 조작해 검증한다. 개발 서버(`npm run dev`, 포트 3000)를 먼저 띄운다. 네이티브 `alert`/`confirm`/`prompt`는 자동화가 멈추므로 코드에 넣지 않는다.

### 정상 흐름

- [ ] `http://localhost:3000/projects` 진입 → 카드가 기대한 건수·순서로 렌더된다 (스냅샷으로 제목 순서 확인)
- [ ] 첫 카드의 제목 링크 클릭 → `/projects/[slug]`로 이동하고 `<h1>`이 카드 제목과 일치한다
- [ ] 상세 하단 외부 링크가 `target="_blank" rel="noreferrer"`를 갖는다
- [ ] 브라우저 뒤로 가기 → 목록으로 복귀한다

### 예외·엣지 케이스

- [ ] 존재하지 않는 slug(`/projects/no-such-slug`) → 404 페이지(`not-found.tsx`)가 렌더된다
- [ ] 미발행 slug 직접 접근 → 404 (초안 내용이 노출되지 않는다)
- [ ] `.env.local`의 `NOTION_API_KEY`를 잘못된 값으로 바꾸고 서버 재기동 → 목록에 "프로젝트를 불러오지 못했습니다" 안내가 보이고 흰 화면이 아니다. 확인 후 원복한다
- [ ] 발행 0건 상태(모든 `Published` 해제) → 빈 상태 문구가 보이고 404가 아니다. 확인 후 원복한다
- [ ] 서버 콘솔에 필수 속성 누락·Slug 중복 경고가 기대대로 찍힌다 (해당 시나리오가 있는 작업만)

### 반응형·다크 모드·접근성

- [ ] 뷰포트 375px / 768px / 1280px에서 가로 스크롤이 없다 (`document.documentElement.scrollWidth <= innerWidth`)
- [ ] 375px에서 1열, 768px에서 2열, 1280px에서 3열이다 (그리드 작업만)
- [ ] 테마 토글로 다크 모드 전환 → 텍스트·배경 대비가 유지되고 하드코딩 색이 없다
- [ ] 접근성 스냅샷에서 제목 링크에 접근 가능한 이름이 있고, 이미지에 `alt`가 있으며, heading 레벨이 건너뛰지 않는다
